# 扁平生图回文的 slotid 字段串行修复 · 0.2.42

用户提供的三个编号 `slotid: 1`、`slotid: 2`、`slotid: 3` 均为合法正整数，但第 2、3 段在编号后附带了 `生成点:`。扁平解析器不识别这个附带字段，且允许所有字段续行，导致编号被解析成 `2\n生成点: ……` 和 `3\n生成点: ……`。后续 `Number(...)` 得到 `NaN`，于是错误报告“slotId 必须是正整数”。

修复位于 `src/domain/model/flat-imagegen.js`：

- 识别 `生成点:`、`anchorSentence:`、`anchor:` 及其他附带字段（含全角冒号）作为边界，忽略其内容和续行；字段名支持大小写和常见 Markdown 加粗。
- `slotid` 和 `size` 只读取字段所在行，不再拼接后续说明。
- `analysis`、`scene`、`scene_uc`、`char`、`char_uc` 继续支持多行；`Foreground:` 等分析内容正常保留。
- 编号校验维持原有 1..9999 的整数要求，不使用 `parseInt` 截取非法编号的数字前缀。
- 生成点仍由召回结果提供，模型附带的定位文本不会覆盖已确认的锚点。

原始回文（含末尾未写完的角色标签）保存为 `tests/fixtures/imagegen-slotid-anchor-output.txt`。编号可以正确读出；第三段缺少第二个角色的 `char_uc` 会由新增结果校验指出，并按预设重试，程序不自行补写提示词。

验证：

- 修复前原文复现：第一项成功，第 2、3 项均返回 `SLOT_PLAN_ID`；新增领域回归检查中 6 项失败。
- 回归检查覆盖原文三图编号解析、额外字段隔离、全角冒号和英文定位别名、单图解析、多行文本保持、非法编号拒绝，以及楼层写 slot 和外部 `generateSinglePrompt` 共用服务路径。完整结果使用召回提供的锚点；原始截断回文会带着第三段缺少 `char_uc` 的问题触发纠错重试。
- 未调用实际模型或 NovelAI；原文中末尾标签截断的问题未在本修复中补写。

预设配置、必填校验与纠错重试见 [结果纠错重试说明](preset-output-retries-2026-10-21.md)。
