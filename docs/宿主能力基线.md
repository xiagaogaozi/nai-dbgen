## 2. 楼层渲染管线（决定 slot 机制）⚠️

`messageFormatting`（`public/script.js:1800`）的**确定顺序**，官方 docstring 自述于 `script.js:1772-1786`：

```
1  仅 messageId===0 的宏替换          script.js:1805
2  comment / hidden 归一化            script.js:1816
3  prompt-bias 剥离                   script.js:1827
4  ▶ MessageFormatter: beforeRegex    script.js:1855
5  正则脚本 getRegexedString           script.js:1860   (isMarkdown:true)
6  ▶ MessageFormatter: afterRegex     script.js:1866
7  fixMarkdown                        script.js:1871
8  encode_tags（默认 false）           script.js:1875
9  showdown.makeHtml                  script.js:1892-1935
10 ▶ MessageFormatter: afterMarkdown  script.js:1948   ← 最后一个可改文本的时机
11 发言人名前缀剥离                    script.js:1951-1953
12 DOMPurify.sanitize                 script.js:1957-1968
```

**官方 docstring 自身已过时**，别照它抄：它把 prompt-bias 算作第 1 步、漏写了
`messageId===0` 的宏替换，也没提第 11 步的发言人名前缀剥离。上表是按**实际代码**核出来的。
本插件的 slot 机制只依赖「展示期正则早于 showdown」这一条，编号漂移不影响选型，
但改动本层代码时要按实际顺序核，不要信 docstring。

### 2.1 `<IMG>…</IMG>` 的真实归宿 —— 已证伪原方案

- showdown 配置见 `script.js:521-532`，未禁用 raw HTML，`<IMG>` 原样穿过 → `<p><IMG>\n1\n</IMG></p>`
- DOMPurify 3.4.2 默认允许 `img`，ST 未设 `ALLOWED_TAGS`（配置仅 `MESSAGE_SANITIZE:true` + `ADD_TAGS:['custom-style']`，`script.js:1957-1965`）
- 结果：`<p><img>\n1\n</p>` —— **void 标签吞掉闭合标签，字面量被摧毁**

**但这只在"没人更早拦截它"时才会发生。** 展示期正则在**第 5 步**执行，
早于 showdown（第 9 步）和 DOMPurify（第 11 步）——`<IMG>` 根本活不到被解析成 `<img>` 那一刻。

→ **用展示期正则（`AI_OUTPUT` + `markdownOnly:true`）替换 slot，原格式即可保留。**
第 4/6/10 步的 MessageFormatter 钩子是备选，但第 10 步在 showdown **之后**，是最差的位置。

### 2.2 MessageFormatter 钩子 API

```js

// stage:  'beforeRegex' | 'afterRegex' | 'afterMarkdown'（默认）
// order:  EARLIEST=0 EARLY=10 NORMAL=50 LATE=90 LATEST=100
```

`public/scripts/message-formatter.js:184-189`、`st-context.js:246`
**故意没有 post-sanitize 阶段**（`message-formatter.js:18-23`）。

## 4. 正则脚本

```js
// public/scripts/extensions/regex/engine.js:334-381
(script.markdownOnly && isMarkdown) ||
(script.promptOnly   && isPrompt)   ||
(!script.markdownOnly && !script.promptOnly && !isMarkdown && !isPrompt)
```

| 事实 | 依据 |
| --- | --- |
| `regex_placement.MD_DISPLAY = 0` **已废弃**，`messageFormatting` 不再选它 | `engine.js:281-292`、`script.js:1860` |
| 迁移逻辑会把 MD_DISPLAY 从存量脚本里剥掉 | `regex/index.js:1389-1392` |
| 展示期跑的是 `AI_OUTPUT` + `markdownOnly:true` | `script.js:1860-1864` |
| 提示词期跑的是 `AI_OUTPUT` + `promptOnly:true` | `script.js:4501-4507` |
| 无 `registerRegexScript` API；只能改 `extension_settings.regex` 再存盘 | `engine.js:113` |

### 4.1 `findRegex` 的分隔符陷阱 ⚠️

`findRegex` 字段是**字符串形式的正则字面量**，由 `regexFromString` 按 `/…/flags` 解析
（`utils.js:1387-1401`）。它靠找分隔符 `/` 来切出 pattern 与 flags。

所以 `</IMG>` 里的那个 `/` **会把解析截断**。必须写成转义形式：

```
✗  /<IMG>(\d+)</IMG>/gi     ← pattern 被 </IMG> 的斜杠截断
✓  /<IMG>(\d+)<\/IMG>/gi
```

本插件的 `assets/regex/*.json` 与 `regex-script.installer.js` 必须始终产出转义形式。
这不是风格问题，写错会让整条 slot 机制静默失效。

### 4.1 `replaceString` 不是静态模板 —— 宏会被执行

```js
// engine.js:391-448  runRegexScript 末尾
const replaceString = regexScript.replaceString.replace(/{{match}}/gi, '$0');
const replaceWithGroups = replaceString.replaceAll(/\$(\d+)|\$<([^>]+)>/g, …); // 先展开 $1
return substituteParams(replaceWithGroups);                                    // 后跑宏
```

顺序是**先展开捕获组、后跑宏**，所以 `{{myMacro::$1}}` → `{{myMacro::3}}` → 调进插件注册的宏 handler。

| 事实 | 依据 |
| --- | --- |
| `{{name::arg}}` 双冒号参数语法 | `MacroLexer.js:83`（`Args.DoubleColon`）、`MacroParser.js:136-145` |
| 宏返回值**不做 HTML 转义**，只 `String()` 归一 | `MacroEngine.js:332-348`、`MacroRegistry.js:459-460` |
| 宏返回值**不被二次扫描宏**（除非 handler 主动 `resolve`）| `MacroCstWalker.js:138` |
| handler 必须同步 | `MacroRegistry.js:101` typedef |
| 正则路径调的是裸 `substituteParams(…)`，不禁用自定义宏 | `engine.js:443` |

**结论**：正则可以吐出完整 HTML，也可以通过宏查插件状态。唯一限制是产物要穿过
showdown 与 DOMPurify（§2.3），以及 handler 必须同步。

### 4.2 正则脚本的可靠性边界

| 事实 | 依据 |
| --- | --- |
| 执行顺序 GLOBAL → PRESET → SCOPED，各自数组序 | `engine.js:12-16, 98-99, 347-376` |
| 别的全局正则可能先跑并改掉同一个标记 | 同上 |
| `getRegexScripts()` **已导出**，可自检脚本是否被删改 | `regex/index.js:17` |
| 用户可禁用/编辑/删除/改顺序 | `#regex_container` UI |
| 整个 regex 扩展被禁用会短路 `getRegexedString` | `disabledExtensions.includes('regex')` |
| 展示期正则只跑非 system 楼；AI 楼走 `AI_OUTPUT`，用户楼走 `USER_INPUT` | `script.js:1832-1864` |
| 每次渲染都重跑（含 `printMessages` 与流式更新）；只缓存编译后的 RegExp（LRU 1000） | `RegexProvider` |

## 6. 世界书

### 6.1 `getWorldInfoPrompt`

```js
// world-info.js:892，已挂在 getContext()（st-context.js:283）
getWorldInfoPrompt(chat: string[], maxContext: number, isDryRun: boolean, globalScanData: WIGlobalScanData)
  → { worldInfoString, worldInfoBefore, worldInfoAfter, worldInfoExamples,
      worldInfoDepth, anBefore, anAfter, outletEntries }
```
- `chat` 是**字符串数组、最新在前**。`script.js:4624` 之所以有 `.reverse()`，是因为它的
  `coreChat` 本身是旧→新。**若调用方手上的窗口已经是新→旧，就不要再 reverse**
- `worldInfoString = worldInfoBefore + worldInfoAfter`，**中间无分隔符**（`world-info.js:898,5265`）
- `globalScanData` 形状见 `world-info.js:104-113`
- `world_info_include_names`（决定扫描文本是否带 `发言人:` 前缀）**不在 `getContext()` 上**，
  需从 `/scripts/world-info.js` 的模块导出取（`world-info.js:74`），默认 `true`。
  取不到时按 `true` 兜底

### 6.2 dryRun **不是**无副作用 ⚠️

| 被抑制 | 仍然发生 |
| --- | --- |
| 不发 `WORLD_INFO_ACTIVATED` | `#ensureChatMetadata()` 改 `chat_metadata.timedWorldInfo` |
| sticky/cooldown 不处理不写入 | **改写作者注释** `setExtensionPrompt(NOTE_MODULE_NAME,…)`（`world-info.js:5268-5276`，**未受 isDryRun 保护**）|
| | `buffer.resetExternalEffects()` 无条件清 `externalActivations` |

**补充**：改写作者注释这一步除了不受 `isDryRun` 保护，还另受 `shouldWIAddPrompt` 门控
（`authors-note.js:28`，在 `world-info.js:5268` 处判断）。也就是说副作用**并非每次必然发生**，
取决于作者注释模块当时的状态。

**结论**：本插件每次生图都要调它，所以快照/回滚作者注释是**必做项**，不是可选项。
既然触发条件依赖运行时状态，就不要去判断"这次会不会改"——**无条件快照、`try/finally` 无条件恢复**，
调用前不存在该项则恢复为删除。判断条件反而会引入新的错误来源。

### 6.3 历史楼的已注入世界书 —— 可恢复，但本项目不用

ST 自己就存了每楼的提示词拆解：

| 项 | 值 | 依据 |
| --- | --- | --- |
| 存储 | localforage 实例 `SillyTavern_Prompts` | `itemized-prompts.js:15` |
| 主键 | chatId；条目内按 `mesId`（楼层下标） | `script.js:5340-5380` |
| 含字段 | **`worldInfoString`**、`rawPrompt`、`storyString`、`finalPrompt`… | 同上 |
| 暴露 | **不在 `getContext()` 上**；有 `ITEMIZED_PROMPTS_LOADED/SAVED/DELETED` 事件 | `events.js` |

**结论**：这是「第 N 楼生成当时注入了什么」的唯一可信来源，只读、零副作用。

**但本项目不使用它。** 生图需要的是"基于当前正文会激活什么"，而这份记录是
"生成当前正文之前激活了什么"——描述的是上一个场景。两者不是同一个东西。
保留本节仅作事实备查（例如将来要做"复现某楼当时的提示词"功能）。
若使用，注意 `mesId` 是楼层下标，删楼后会错位，需交叉校验。

### 6.4 关键字匹配语义（需镜像）

```js
// world-info.js:337-366  matchKeys —— 未导出，必须自行复刻
matchKeys(haystack, needle, entry) {
    const keyRegex = parseRegexFromString(needle);
    if (keyRegex) return keyRegex.test(haystack);          // 正则键：不做大小写变换
    haystack = transform(haystack, entry);                  // 非大小写敏感则 toLowerCase
    const s = transform(needle, entry);
    if (entry.matchWholeWords ?? world_info_match_whole_words) {
        if (s.split(/\s+/).length > 1) return haystack.includes(s);   // 含空格 → 退化为包含
        return new RegExp(`(?:^|\\W)(${escapeRegex(s)})(?:$|\\W)`).test(haystack);
    }
    return haystack.includes(s);
}
```

| 符号 | 是否导出 | 位置 |
| --- | --- | --- |
| `matchKeys` / `WorldInfoBuffer` | ❌ 模块私有 | `world-info.js` |
| `parseRegexFromString` | ✅ | `world-info.js:2901` |
| `escapeRegex` | ✅ | `utils.js:1377` |

复刻易错点：
1. 词边界用 `\W` **不是** `\b`
2. 多词键**绕过**全词匹配
3. **空键 `includes('')` 恒为 true** —— 必须前置过滤
4. 正则键完全覆盖大小写与全词开关
5. 全局默认 `world_info_case_sensitive=false`、`world_info_match_whole_words=false`（`world-info.js:77-78`）；单条覆盖字段 `caseSensitive` / `matchWholeWords`

## 7. 宏系统 —— 中文变量名不可行 ⚠️

```js

export const MACRO_IDENTIFIER_PATTERN = /^[a-zA-Z][\w-_]*$/;   // 无 u flag，\w 即 ASCII
```

### 8.4 LLM —— 自定义（兼容 OpenAI）+ 密钥库 ✅

对应需求 4.9：插件走 `chat_completion_source:'custom'`，**不**再使用 `openai`+`reverse_proxy`+`proxy_password`。

**/status 拉模型**（`chat-completions.js:1778+`，custom 分支约 1800–1804）：
- `custom_url` + `readSecret(SECRET_KEYS.CUSTOM, secret_id)` + `custom_include_headers`
- `GET <url>/models` → 原样回传（常见 `{ data: [{ id }] }`，约 2072–2110）

**/generate**（custom 分支约 2394–2421；收尾 2600–2672）：
- 读 `custom_url`、`secret_id`、`custom_include_body`（`mergeObjectWithYaml` 进 `bodyParams`，最后 `...bodyParams` 覆盖顶层）、`custom_include_headers`、`custom_exclude_body`（2672）
- `custom_prompt_post_processing` 在入口 2246 行对 messages 预处理
- 通用参数：`temperature` / `top_p` / `top_k` / `max_tokens` / `presence_penalty` / `frequency_penalty` / `seed` / `stop`
- 顶层 `reasoning_effort` **只**对 `OPENAI_REASONING_EFFORT_MODELS`（及 koboldcpp/）转发（2600）→ 用户填了推理强度必须经 `custom_include_body`；用户自己的追加请求体优先

**客户端** `ChatCompletionService.createRequestData`（`custom-request.js:428-451`）：
显式字段 + `...props`，会透传 `secret_id` / `custom_include_body` 等；`sendRequest` → `POST /api/backends/chat-completions/generate`（463）。

**发送前模板事件（2026-10-20 核对）**：`sendRequest` 本身不触发 `CHAT_COMPLETION_SETTINGS_READY`。
主回复由 `openai.js:3146` 在 HTTP 之前 `await eventSource.emit(...)`；shujuku 的 `if` / 数据库变量处理依赖此事件。
nai-dbgen 在最终预设变量和多模态内容组装完成后，经 `adapters/host/chat-completion.bridge.js` 等待同一事件，
再检查是否残留 `<if seed/cell/cond/db/sql=...>`。有残留时返回不可重试错误，停止发送。
详见 [shujuku 条件模板兼容记录](shujuku-if-template-2026-10-20.md)。

**密钥库**（`src/endpoints/secrets.js`，`SECRET_KEYS.CUSTOM='api_key_custom'`）：
| 路由 | 行为 |
| --- | --- |
| `POST /api/secrets/read` | 返回各 key 的打码条目列表（含 `id/value/label/active`） |
| `POST /api/secrets/write {key,value,label}` | 返回 `{id}`；**会把该 key 下全部设为非激活、新写的设为激活**（`writeSecret` 204–222） |
| `POST /api/secrets/rotate {key,id}` | 切激活 |
| `POST /api/secrets/delete {key,id}` | 删后若无人激活则抬第一个（249–252） |
| `POST /api/secrets/rename {key,id,label}` | 改备注 |

因此插件写 Key 必须：read 记激活 id → write → rotate 切回。请求头用 `getRequestHeaders()`。

**边界**：若 CUSTOM 下原先没有任何密钥，写入后插件的就是唯一激活项；源码**没有**「全部去激活」API，无法在只剩一条时去激活。删非激活项不改主连接；删激活项会抬第一个。

**YAML**：酒馆前端 `public/lib.js` 导出 `yaml`（npm `yaml`）；服务端 `mergeObjectWithYaml`（`src/util.js:844`）同库。插件校验用自研子集 + JSON（无运行时第三方依赖）。

数值范围对齐 Chat Completion 界面（`index.html`：温度 0–2、Top P 0–1、Top K 0–500、max_tokens 1–128000、惩罚 -2–2、seed -1–2147483647）。

### 本插件用法（库 / 配置 / 画师示例图）

- **库、预设、API 配置**：每类一个固定名 `nai-dbgen_*.json`，经 `/api/files` 整文件覆盖；启动加载到内存，404=空，其它读失败→该库不可用且禁止空写回。
- **画师串示例图**：`nai-dbgen_artist-preview_<安全化id>.png|webp`，展示用 `/user/files/<name>?t=…`。
- **会话生图记录 / 编号 / 目录 / 图片缓存（B 路）**：
  - 会话 id = `chat_metadata.integrity`（`script.js` loadChat 缺失时会 mint；分支会话新 integrity）。宿主 `getSessionId()` 对齐：缺失则生成并 `saveMetadataDebounced`。
  - 会话文件 `nai-dbgen_chat_<安全化id>.json`；目录 `nai-dbgen_index.json`（含 `chatFileName` + `avatarUrl`/`groupId` 供清理核对）。新建：**先登记目录再上传文件**。
  - 只保留最近 N 条 AI 楼（N=`contextWindowSize`）的记录；写/载时修剪。
  - slotId：最新带 `<IMG>` 的楼（**全部 swipe**）取 max+1；编号复用前清旧记录与缓存图。
  - 图片：IDB `images` + `slot_image_cache[sessionId,slotId]`。超出保留：有缓存照常显示不可再出；无缓存显示「已超出保留范围」。
  - 事件：`CHAT_DELETED` / `GROUP_CHAT_DELETED`（`events.js`）删文件+目录条目；`CHAT_RENAMED` 更新目录名。清理：`POST /api/characters/chats`（`metadata:true`）+ 群组 `chats`/`chat_id` + `/api/files/verify`。
  - **不写** `message.extra['nai-dbgen']`。
- **楼层 slot 图 / 工作台预览**：仍为浏览器 IndexedDB 缓存（B 路）。

图片端点补充（`/api/images`，本插件楼层图主路径不用它）：
- 允许格式含 `png` `webp`（`src/constants.js:528-552`）
- 无单图大小校验，全局 body 上限 500mb（`server-main.js:110`）

## 10. 预设格式（导入）

ST 聊天补全预设是**扁平对象**：连接/采样键 + `prompts[]` + `prompt_order[]`。
样例：`default/content/presets/openai/Default.json:51-178`。

```jsonc
{ "temperature": …, "openai_max_context": …,          // 我们不需要的连接/采样键
  "prompts": [ { "identifier":"main", "name":"Main Prompt", "role":"system",
                 "system_prompt":true, "content":"…" },
               { "identifier":"chatHistory", "marker":true } ],
  "prompt_order": [ { "character_id":100000,
                      "order":[ {"identifier":"main","enabled":true}, … ] } ] }
```

`Prompt` 字段（`PromptManager.js:80-196`）：`enabled` `identifier` `role` `content` `name`
`system_prompt` `position` `injection_position`(RELATIVE=0/ABSOLUTE=1) `injection_depth`
`injection_order`(默认100) `forbid_overrides` `extension` `injection_trigger` `marker`。

内置 marker：`main` `nsfw` `jailbreak` `chatHistory` `worldInfoBefore` `worldInfoAfter`
`dialogueExamples` `charDescription` `charPersonality` `scenario` `personaDescription`
`enhanceDefinitions`（`PromptManager.js:2001-2136`）。装配入口 `populateChatCompletion`
（`openai.js:1185-1257`）→ `ChatCompletion.getChat()`（`openai.js:4120-4140`）。

**结论**：「与酒馆同等能力」的可导入内核 = `prompts[] + prompt_order[]` + 逐条
`identifier/role/enabled/injection_*`。角色卡/历史/世界书 marker 与本插件无关，
本插件定义自己的四个块 marker。导入器只吃 `prompts` + `prompt_order`，丢弃连接采样键。
